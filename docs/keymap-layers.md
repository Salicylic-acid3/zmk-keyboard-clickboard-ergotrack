# ClickBoard ErgoTrack のレイヤー構成

ZMK Studio / Keeb-On! Studio でキーマップを編集するときの手引きです。
このキーボードにはトラックパッドの都合で「仕組みのために使っているレイヤー」が
あるので、どれを触ってよくて、触るとどうなるのかをまとめます。

## レイヤー一覧

| index | 表示名 | 用途 | 編集 |
| - | - | - | - |
| 0 | Base | 通常のキーマップ | 自由 |
| 1 | Alt Base | OS別のベースレイヤー枠 | 自由 |
| 2 | Drag | 左クリック保持中だけ有効 | 条件付きで可(下記) |
| 3–10 | (未使用) | Studio から自由に追加 | 自由 |

`extra1`〜`extra8` は `status = "reserved"` で確保してある空き枠です。Studio の
レイヤー追加ボタンで初めて実体化します。ZMK はレイヤー数をビルド時に固定するため、
実機で増やすことはできません。8枠で足りなくなったら keymap に `extraN` を足して
ビルドし直してください(1枠あたり 79キー × 約12バイト ≒ 1KB の RAM を使います)。

## 各レイヤーの詳細

### 0: Base

通常のレイヤーです。特別な扱いはありません。

### 1: Alt Base

`zmk-feature-default-layer` が OS 判定や接続先ごとに有効化する枠です。
このモジュールはベースレイヤーを差し替えるのではなく、**指定レイヤーを常時 ON に
します**。したがって:

- 全キーを `&trans` にしておけば、有効になってもレイヤー0がそのまま効きます
- 変えたいキーだけ上書きすれば、そのOSのときだけ差し替わります

**このレイヤーに何かを割り当てるときは、必ず「OSごとに変えたいもの」に限ってください。**
常時 ON になるため、ここに置いたものはそのOSでは常に有効です。

`CONFIG_ZMK_DEFAULT_LAYER_MAX_INDEX=1` なので、default-layer 機能が選べるのは
index 0 と 1 だけです。**このため index 1 に通常のレイヤーを置いてはいけません。**
過去に index 1 をトラックパッド用のモードレイヤーにしていた際、OS判定でそれが常時
ONになり、ポインタが完全に動かなくなる不具合が起きました。

### 2: Drag

物理左クリック(`&drag_lclk` を割り当てた6キー)を**押している間だけ**有効になります。
`drag_lclk` は「左クリック押下」と「`&mo 2`」を同時に行うマクロです。

このレイヤーが存在する理由は、キーではなく**入力プロセッサの切り替え**です。
右シールドの overlay で、両方の listener がこのレイヤー用のオーバーライドを持っています:

- 通常時のチェーン: 末尾に `&dual_pad`(左右各1本指のジェスチャー融合)
- Drag レイヤーのチェーン: `&dual_pad` を**含まない**

つまりドラッグ中はジェスチャー融合が止まり、反対側のパッドに指を置いてもスクロールに
ならずカーソルが動きます。これが「ドラッグの引き継ぎ」を成立させています。

**キーの割り当ては変更して構いません。** 全キー `&trans` にしてあるので、何か割り当てると
「ドラッグ中だけ効くキー」になります。ドラッグ中に使いたい修飾キーなどを置く用途には
向いています。**ただしレイヤー番号(2)を変えたり、レイヤーごと削除したりしないでください。**
`drag_lclk` マクロの `&mo 2` と overlay の `layers = <2>` が壊れます。

## トラックパッド用の仮想キー位置

物理キー 72個の後ろに、トラックパッドのジェスチャー用の位置が7つあります。
Studio 上では実キーと同じように並んで見えます。

| 位置 | 発火条件 | 既定の割り当て |
| - | - | - |
| 72 | ピンチ(片方のパッドで2本指) | `&kp LGUI` |
| 73–76 | 3本指スワイプ(4方向) | `&kp F13`〜`F16` |
| 77 | 左右各1本指のズーム中に保持される修飾キー | `&kp LCTRL` |
| 78 | (未使用) | `&none` |

**これらは自由に割り当て替えできます。** ジェスチャーに好きな機能を割り当てるための
仕組みなので、むしろ変更が前提です。73〜76 が `F13`〜`F16` になっているのは、
どのスワイプ方向がどの位置に対応するかを実機で確認するための仮置きです。

位置77だけは意味が違います。左右各1本指のズーム操作中、`dual_pad` プロセッサが
この位置を押しっぱなしにします。**ホストにズームとして解釈させるための修飾キーを
ここに置いてください。**

## OS ごとに変えたいもの

### ズームの修飾キー

macOS は Cmd+スクロール、Windows は Ctrl+スクロールでズームします。
位置77はキーマップで解決されるので、**Alt Base(レイヤー1)に位置77を上書きすれば、
OS判定でそのまま切り替わります。**

現在 Base では `&kp LCTRL` を割り当てています。この Mac は「システム設定 → キーボード
→ 修飾キー」で Control と Command を入れ替えているため、**LCTRL が Cmd として届きます**。
その設定をやめる場合は `&kp LGUI` に変更してください。

### スクロールの向き

こちらはキーマップではなく入力プロセッサの設定なので、Studio からは変更できません。
`dual_pad` の第2引数がフラグになっていて、デバイスツリーのプロパティと XOR されます:

| bit | 意味 |
| - | - |
| 0 (`1`) | スクロール方向を反転 |
| 1 (`2`) | ズーム方向を反転 |

listener のレイヤーオーバーライドで別の値を渡せば、そのレイヤーだけ向きが変わります:

```dts
        os_alt {
            layers = <1>;
            input-processors = <
                /* ... 通常と同じ並び ... */
                &dual_pad 1 1      /* param2=1 でスクロール反転 */
            >;
        };
```

Windows 実機で正しい向きを確認してから追加するのが確実です。
